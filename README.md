
# MY OBSIDIAN VAULT

 It's a backup of my obsidian notes (programming, tech, studies...) they are not formatted to be properly linked and rendered in GitHub. 
 **and they are being actively organized and created, so they may look a bit chaotic and empty in some topics** 

**Why**:
> When I wanna learn about a topic, I search info about it in a mix of a structured/chaotic way, so I end up with what I searched for, and lots of extra stuff I find interesting. This vault is my attempt at placing all that information in a structured way **that works for me**.

**How**:
> 99% of the vault I write myself, the only thing I do with AI is create a temporary index for a topic I wanna learn about and I don't know where to start. Those indexes eventually are replaced by an actual structure I wanna stablish for that topic once I start taking notes/learning about it, but I find it useful to have a first quick glance about what topics I can go into inside one subject.

**Structure**
> Folders only say which domain a note belongs to. The topic structure lives in index notes (hubs) and in an `up:` property on every note, because I navigate with keybinds -> index -> topic anyway.
> - *home.md*: entry point. Links to every domain and shows the inbox, stub notes and recent notes (Bases).
> - *tech/*: programming, CS, systems, networking, security. Flat, one folder.
> - *math/*, *history/*: same idea for those domains.
> - *college/*: one folder per course, with only logistics, evaluation, exercises and exam prep. The theory goes to the domain folder and the course hub links to it.
> - *root*: inbox. Anything at the root besides `home` and `README` is waiting to be sorted.
> - *Assets*: images pasted into notes, plus Excalidraw drawings.
> - *Templates*: my Templater templates. New notes get `up:` and the header (`# PREFIX > TOPIC`) from their name. I build notes with three sections: 1: Summary, 2: Theory, 3: Questions. First one for a quick definition of the concept, second one for an in-depth view, and the questions are things that are tricky to remember or good interview questions. They're written as Spaced Repetition flashcards so I can actually review them.

**Naming**
> - `prefix_topic`, lowercase snake_case. The prefix is the parent hub and the hub is the bare prefix: `java_streams` -> `java` -> `tech`.
> - File names are unique across the vault, so wikilinks never break when a note moves.
> - I create notes from their hub: type `[[net_osi_model]]` in `net`, click it, and the template does the rest.
